# Автоматический генератор Changelog из коммитов GitHub

## Описание задачи

Реализована система автоматической генерации changelog из коммитов GitHub репозитория с использованием LLM для анализа и структурирования изменений.

## Что было сделано

### 1. MCP сервер для работы с changelog (`server/mcp/servers/changelogMCP.js`)

Создан новый MCP сервер, который предоставляет инструменты для:
- **getCommits** - получение списка коммитов между двумя точками (тегами, ветками или SHA)
- **getTags** - получение списка тегов репозитория
- **generateChangelog** - подготовка данных для генерации changelog

### 2. API endpoints (`server/index.js`)

Добавлены два новых API endpoint:
- `POST /api/changelog/generate` - генерация changelog из коммитов с использованием LLM
- `GET /api/changelog/tags` - получение списка тегов репозитория

### 3. Frontend компоненты

- **Сервис** (`src/services/changelog.ts`) - клиентский API для работы с changelog
- **Страница** (`src/pages/ChangelogPage.tsx`) - полнофункциональный UI для генерации changelog
- **Навигация** - добавлена ссылка в главное меню приложения

## Пайплайн работы

1. **Получение коммитов**: ChangelogMCP сервер получает коммиты из GitHub API между указанными точками (since/until)
2. **Подготовка данных**: Коммиты форматируются для передачи в LLM
3. **Генерация changelog**: LLM анализирует коммиты и создает структурированный changelog
4. **Отображение**: Результат отображается в UI с возможностью скачать в формате Markdown или JSON

## Использование

### Через UI

1. Откройте приложение и перейдите в раздел "Changelog"
2. Укажите параметры:
   - **Since** - начальная точка (тег, ветка или SHA)
   - **Until** - конечная точка (по умолчанию HEAD)
   - **Branch** - ветка для анализа (по умолчанию main)
   - **Модель LLM** - выберите модель для генерации
   - **Формат** - Markdown или JSON
3. Нажмите "Сгенерировать Changelog"
4. Результат отобразится на экране с возможностью скачать

### Через API

```bash
# Генерация changelog
curl -X POST http://localhost:3001/api/changelog/generate \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "since": "v1.0.0",
    "until": "HEAD",
    "branch": "main",
    "modelType": "deepseek",
    "format": "markdown"
  }'

# Получение тегов
curl -X GET http://localhost:3001/api/changelog/tags \
  -H "Authorization: Bearer YOUR_TOKEN"
```

## Требования

### Переменные окружения

- `GITHUB_TOKEN` - токен GitHub для доступа к API (опционально, но рекомендуется)
- `DEEPSEEK_API_KEY` или другие ключи LLM в зависимости от выбранной модели

### Зависимости

Все зависимости уже включены в проект:
- `@octokit/rest` - для работы с GitHub API
- `react-markdown` - для отображения Markdown
- LLM handlers (deepseek, yandex, chatgpt, huggingface)

## Особенности реализации

1. **Гибкая работа с тегами и ветками**: Система автоматически определяет, является ли входное значение тегом, веткой или SHA
2. **Обработка больших объемов**: Поддержка пагинации и ограничение максимального количества коммитов
3. **Интеграция с существующей архитектурой**: Использует MCP оркестратор и существующие LLM handlers
4. **Безопасность**: Все endpoints требуют авторизации через JWT токен
